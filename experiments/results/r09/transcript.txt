  The failure looks like an API bug rather than a test mistake.

  The new file is tests/api/bookings/create-booking-validation.spec.ts. It
  follows the same table-driven pattern as the existing
  create-user-validation.spec.ts. The typecheck passes.

  Rejection cases. Each one checks for a 400, code: VALIDATION_ERROR, and that
  errors lists exactly the invalid fields:
  - checkIn: missing; not in YYYY-MM-DD format.
  - checkOut: missing; not in YYYY-MM-DD format; not a real date (2030-02-30);
    same day as check-in; before check-in.
  - guests: missing; 0; 9; 2.5.
  - Two invalid fields at once (checkIn missing and guests 0): checks that both
    appear, one entry each.

  Boundary cases that should succeed (201, then the booking is deleted): 1
  guest, 8 guests, and a one-night stay.

  The failure: rejects booking when checkOut is not a real date got 201 instead
  of 400. The API accepts 2030-02-30 as a check-out date. Criterion 1 says the
  dates "must be dates in YYYY-MM-DD format", and I read that as requiring a
  real calendar date. If you read it as a format check only, this test is wrong
  and should be removed. Otherwise it's a bug in a ticket marked "Done (in
  production)".

  Two things to know:
  - A test booking was left in the service. Because the API accepted that
    request, it created a booking, and the rejection tests don't clean up.
    There's no list endpoint, so I couldn't find its ID to delete it. It will
    happen again on every run until the bug is fixed or the test changes.
  - The out-of-order date tests assume the error is reported on checkOut. The
    ticket doesn't say which field gets the error when check-out is on or before
    check-in. That's how the API behaves now (those tests pass), but you may
    want the ticket to say so explicitly.

  How do you want to handle the failing test? I can leave it failing to flag the
  bug, mark it as an expected failure (test.fail) with a note pointing to a bug
  ticket, or remove it. Separately, I can make the rejection tests delete any

  haven't committed anything.
