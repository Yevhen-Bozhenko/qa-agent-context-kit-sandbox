  Which defect each negative test catches

  - checkOut before checkIn: fails if the API doesn't compare the two dates, or
    reports the error under the wrong field.
  - checkOut equals checkIn: fails if the rule is implemented as "on or after"
    (>=) instead of "strictly after" (>).
  - guests = 0: fails if the lower bound is missing or set to 0 instead of 1.
  - guests = 9: fails if the upper bound is missing or set above 8 (for example,
    <= 9).
  - checkIn missing: fails if checkIn isn't required, or if its absence crashes
    the date comparison or produces extra errors. Each test checks for exactly
    one error field.

  The boundary tests (guests = 1, guests = 8, checkOut one day after checkIn)
  check the other side: they fail if the limits are set too tight.
